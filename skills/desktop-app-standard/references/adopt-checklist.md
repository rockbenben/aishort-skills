# 升级采用清单

先按[依赖升级](upgrade-dependencies.md)确定实际解析版与目标版，再读两者之间的上游变更。只迁移项目使用的能力；版本、支持期和预发布计划从[官方来源](sources.md)查询，不在本页维护发布快照。

## 按使用面筛选变更

| 使用面 | 需要核对的变化与验收 |
| --- | --- |
| Electron preload、IPC 与权限 | 目标版本可用的模块/全局对象、preload 作用域、权限事件名称及调用方。缺失 API 按迁移方案处理，不以关闭 sandbox 恢复旧行为。 |
| 系统凭证存储 | 同步/异步 API、平台后端和失败处理；用既有数据验证升级后仍可读取。 |
| ASAR 与原生模块 | 原始文件描述符、临时提取、unpack 路径和 ABI；在实际打包产物中调用消费方。 |
| 窗口与系统集成 | 状态恢复、子窗口关系、托盘、登录启动、屏幕捕获与外链；检查应用是否依赖已变更的行为。 |
| Tauri JS/Rust 与插件 | 按[配套规则](tauri.md#版本配套)核对解析版本、初始化和 capability，避免只改一侧包版本。 |
| Tauri 安装器与重启 | 自定义语言字符串、降级策略、平台标志和重启时的进程环境；从旧安装版验证。 |
| 生命周期与资源 | 窗口关闭后的监听器、后台任务及协议读取，测试重复打开和慢路径。 |
| 更新与分发 | 按[发布流程](release-flow.md)核对旧 updater 对新清单和签名的兼容性。 |

## 采用新能力

当官方新 API 能替代现有维护负担时，先确认稳定性、平台门槛和实际收益，再决定采用。实验接口与未来版本计划用于评估，不作为稳定应用的默认依赖。

涉及性能的变更按[相同条件复测](verification-performance.md#性能测量约定)，不从发布说明中的优化直接推断本应用会变快。具体框架边界见 [Electron](electron.md) 和 [Tauri](tauri.md)。
