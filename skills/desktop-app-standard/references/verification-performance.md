# 验证与优化：先有基线，再声称提升

全面维护时按项目适用的层次检查。局部任务只验证受影响的路径，例如打包资源变动后在安装版中打开该资源。涉及性能的改动先测基线，再按相同条件复测。

## 执行前

- 把允许的改动、可运行命令、平台和外部副作用写清。项目 test/build 是执行代码；初始只读审计不会自动运行它们。
- 检查工作树、工具链、锁文件与网络条件；保留用户未提交改动。
- 无 Windows/macOS 环境时不要把 Linux 编译/模拟器测试标作对应 OS 通过；证书存在也不等于签名验收通过。

## 最小验证矩阵

| 层次 | 验证 |
|---|---|
| 静态 | lint/typecheck、Rust fmt/check/clippy（项目允许时）、workflow lint、配置 schema |
| 单元与集成 | IPC 参数/调用方、权限、错误路径、数据库/设置迁移、深链输入 |
| 开发运行 | main/preload/renderer 或 Rust/webview；被触及 API 的真实路径 |
| 打包运行 | 原生模块、ASAR/资源路径、CSP、自定义协议、生产窗口、无 DevTools |
| OS 体验 | 首次安装/卸载、DPI/多屏、主题、菜单/托盘/快捷键、键盘可达、离线启动 |
| 更新 | 旧安装版到新版本、坏签名/断网/重试/权限失败、重启与数据保留、渠道隔离 |

执行原项目相应命令，不凭空假设每个项目都有 `npm test` 或某个 dist script。执行失败要记录命令、环境、退出状态、证据，不“修成永远通过”。

## 多端同步与断网恢复

仅在应用涉及多端共享状态时执行；先补能复现实际问题的回归测试，再修复。

- 将版本比较与写入视为同一个原子操作。WebDAV 整文件同步使用强 ETag 的 If-Match 更新、If-None-Match: * 创建，或经验证的锁机制；弱 ETag、秒级时间戳和无条件覆盖不能替代原子版本保护。服务能力不足时明确停止，不能静默降级。
- 304 只证明远端表示未变，不证明前次密文已解密或本地事务已提交。返回完整缓存供重验，或将“不变”快路径绑定到可证明的本地提交状态；写入结果不明确后重试先重读。跨平台 HTTP 桥统一响应头名大小写。
- 用两个隔离的数据存储和客户端状态运行实际合并流程；本地 HTTP 服务可固定两次读取到同一版本，再同时放行，确定性覆盖首次创建、同版本更新、设置与删除标记的收敛。仅 mock push 的成功/冲突结果不足以验证传输协议。
- 分别注入读取断线、写入前断线、服务端已写入但响应丢失、连续冲突和解密失败。验证失败不记成功、本地改动保留、重试不丢不重复，并为冲突重试设上限。
- 分开报告本地协议模拟、真实服务和设备验收；客户端发送条件头不代表服务端确实原子执行。模拟 HTTP 或原生桥接口测试不能冒充真实网盘与手机的往返同步。

## 性能测量约定

Electron 官方建议 profile 实际运行代码，定位成本最高的部分后迭代优化，而不是依赖通用清单承诺提升。[Electron 性能指南](https://www.electronjs.org/docs/latest/tutorial/performance)

- 用相同硬件/OS/电源模式/发布构建/测试数据，写明 framework/toolchain/commit。
- 分开记录进程创建→首屏→可交互，冷启动与热启动分组。建议每组至少 5 次；样本少时不报告不可靠的 p95。
- 空闲稳定后记录**整个进程树**内存与 CPU，说明 RSS/working set/私有内存指标；不同 OS 指标不要直接混比。
- 下载大小、安装占用、解压后大小分别记录；不要把压缩包小误写成内存减少。
- UI 长任务、IPC 往返、关键操作耗时、更新下载/安装时间、CI 各阶段耗时按需求纳入。
- 原始记录可放 `templates/performance-record.md`；缺失就写待测，不生成百分比。

## 候选优化（必须由测量驱动）

- 启动：延迟非必要初始化/网络更新检查；拆分重依赖、恢复上次窗口状态但处理离屏；避免白屏。
- Electron：避免 main 中同步 I/O/同步 IPC，CPU 重活移到 worker/utility 进程；清理窗口/监听器/定时器；验证 preload 边界。[Electron 性能指南](https://www.electronjs.org/docs/latest/tutorial/performance)
- Tauri：避免阻塞异步执行器/UI 线程，正确安排阻塞/CPU 任务；减少不必要 IPC 序列化/拷贝；限制插件与 capability。
- 渲染：长列表虚拟化、按需加载、资源压缩、释放对象 URL/缓存/不可见页面资源。
- 打包：仅包含所需资源与目标架构；检查 source map、测试文件和开发依赖；Rust LTO/strip/codegen-units/优化等级先对目标包测量，兼顾构建时间和调试能力。
- CI：按 OS/架构/toolchain/lock key 缓存；不以跳过必需测试或共享不可信产物来加速。

每次只改一个假设或一个可回滚主题；相同协议复测。若收益不稳定、错误率增加或安全变弱，则撤回/暂缓，不把“版本更高”当性能结论。
