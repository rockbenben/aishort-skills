- 0.7.1：Electron 发布模板里一个**实测踩到**的坑。GitHub 把「仓库里没有这个 secret」渲染成**空字符串**（不是不设置该变量），而 electron-builder 把空的 `CSC_LINK` 理解成「证书就是这个路径」，于是拿工作目录当证书文件去签——macOS 那条腿直接失败：`⨯ /Users/runner/work/<repo>/<repo> not a file`，Windows 与 Linux 不受影响，看着像平台问题、其实是凭据为空。模板改为用别的名字收下 secret，只在真的有值时才导出成 electron-builder 认的名字，并把 `CSC_IDENTITY_AUTO_DISCOVERY` 固定为 false（CI 的签名身份只该来自显式凭据，否则结果取决于 runner 镜像上碰巧装了什么）。同一轮还踩到第二个同类的坑：**Windows runner 的默认 shell 是 PowerShell**，多行 bash 脚本在那条腿直接 ParserError，而 macOS/Linux 照常通过——模板的 Build 步骤现在显式 `shell: bash`。这条检查一开始是**文件级**的（文件里有 Windows runner + 有 bash 语法 + 全文没有 `shell: bash` → 报），实测既会误报（bash 脚本只在 Linux-only 的 job 里、Windows 那个 job 只有 `npm ci`）也会漏报（同一文件里 validate job 写了 `shell: bash`，build job 没写 → 全文一搜就放行，**恰恰漏掉了真正出问题的那一版**）；改成**按 job 判定**——只看会落到 Windows runner 上的 job、且该 job 内没有 `shell: bash` 时才报——两个问题一起解决（漏报的那一版实测命中 `P1 @ release.yml:181`，修好后同一仓库 P0/P1/P2 = 0）。还有一个静默的：**命令行上的 target 名会覆盖 electron-builder.yml 里的 target 列表**，配置写了 `portable` 而命令行写 `--win nsis`，免安装版就无声无息地从产物里消失了（v0.4.0 有、v0.5.0 没有）——目标写在配置里、命令行只给架构。新增 `electron-builder-empty-csc-link` 与 `bash-script-on-windows-runner`（均 P1）自动报出这两类写法，并新增 2 个用例，`node --test` 复跑 **62/62**。真实回归：044-md-publisher 的 v0.5.0 第一次发布在 macOS 腿失败（空 CSC_LINK）、第二次在 Windows 腿失败（PowerShell 解析 bash），两次都是「一个平台红、另两个绿」；两次修完后三平台全绿。附带的坑也一并记下：模板里 `CSC_LINK: ${{ runner.os == 'macOS' && secrets.X || '' }}` 这种写法**必然**产生空字符串，与有没有配 secret 无关。
- 0.7.0：Electron 的 macOS 更新链路补上一个真实的坑——electron-builder 的 GitHub publisher 上传时会**改名**（GitHub 资产名只允许 `[0-9A-Za-z._-]`，`my-app Setup 1.0.0.exe` → `my-app-Setup-1.0.0.exe`），并把更新清单的 `url` 改成同一个名字；house style 的 `--publish never` + 手动上传意味着那次改名**不会发生**，清单于是指向一个不存在的资产，应用内更新直接 404。`templates/workflows/release-electron.yml` 现在先按同一规则改名（空格 → 短横线）再上传，并校验清单里每个 `url` 都有对应文件、且指向可自更新的载体（Windows=NSIS、macOS=zip、Linux=AppImage）；SHA256SUMS 改用 `find -print0`，不再把自身算进去。新增 `mac-update-needs-zip`（P1）：mac 目标有 dmg/pkg 却没有 zip 时报出——electron-updater 的 MacUpdater 只在清单里找 zip（`findFile(files,"zip",["pkg","dmg"])` 里的 pkg/dmg 是**排除表**），只有 dmg 时清单指向 .dmg，检查更新抛 `ERR_UPDATER_ZIP_FILE_NOT_FOUND`，构建全绿而 Mac 上「检查更新」100% 失败。`electron-runtime-download` 的影响描述按实测改写：**打包本身不受影响**（electron-builder 自己下载发行包，node_modules/electron/index.js 首次 require 时也会按需自下载），变的是下载时机。打包产物里的 manifest 副本（`release/<platform>-unpacked/resources/app/package.json`）不再算版本来源，报告里不再出现重复行。house style 把 `engines.node`（真实下限，从工具链自身 engines 约束取交集）与 CI 钉版分开，`.nvmrc` 明确为可选。新增 2 个用例，`node --test` 复跑 **60/60**。真实回归：用 044-md-publisher 修复前的 `electron-builder.yml`（`mac.target: [dmg]`，即 v0.4.0 实际发出去的那份）实测命中 `mac-update-needs-zip` P1，定位 `electron-builder.yml:18`；修复后的同一仓库 P0/P1/P2 = 0。
